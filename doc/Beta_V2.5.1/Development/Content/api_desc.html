3.使用JL_BLEKit.xcframework蓝牙连接方式

JL_BLEKit.xcframework依赖于其他的SDK，所以在导入时应包含以下：

JL_OTALib.xcframework——OTA升级业务库
JL_AdvParse.xcframework——杰理蓝牙设备广播包解析业务库
JL_HashPair.xcframework——设备认证业务库
JLLogHelper.xcframework——日志打印业务库

重要

在OTA过程中不允许进行其他命令的交互

3.1. SDK外部蓝牙管理

外部蓝牙管理，在使用 JL_BLEKit.xcframework 的同时，在蓝牙管理部分交由 外边（开发者自定义蓝牙）统筹管理 ，可保障使用时的多样化。

参考Demo：「 JL_OTA项目的 BleByAssist文件夹」 支持的功能 ：

  • BLE设备握手连接；

  • 获取设备信息；

  • OTA升级能实现；

  • 注意：相对于 3.2.2 中描述的所有BLE操作都需自行实现；

会用到的类 ：

  • JL_Assist ：部署SDK类；(必须)

  • JL_ManagerM ：命令处理中心，所有的命令操作都集中于此；(必须)

  • JLModel_Device ：设备信息存储的数据模型；(必须)

BLE参数 ：

  • 【服务号】 ：AE00

  • 【写】特征值 ：AE01

  • 【读 】特征值 ：AE02

3.3. OTA单备份回连

单备份固件的设备在 OTA 升级时需要先下载 BootLoader（Loader）。设备下载完 Loader 后会重启进入 Loader 模式，此时 BLE 连接断开，需要重新扫描并连接设备，再继续发送剩余的升级数据，这个过程称为 回连。双备份固件的设备升级时不会断开连接，无需回连。

备注

升级过程中可通过 JL_OTAResult 回调中的以下状态判断是否需要回连：

  • JL_OTAResultReconnect (0x09)：需要回连，使用设备 UUID 定位；

  • JL_OTAResultReconnectWithMacAddr (0xfc)：需要回连，使用杰理广播包中的 MAC 地址定位；

  • JL_OTAResultReconnectUpdateSource (0xfe)：需要回连（资源升级场景）；

  • JL_OTAResultDisconnect (0xfd)：OTA 过程中设备断开。

SDK 会根据设备能力自动判断回连方式，并写入 JL_OTAManager.otaReconnectType：

1typedef NS_ENUM(UInt8, JL_OTAReconnectType) {
2    JL_OTAReconnectTypeUUID    = 0x00, // OTA升级回连使用 UUID
3    JL_OTAReconnectTypeMACAddr = 0x01, // OTA升级回连使用 MAC 地址
4};

杰理提供了两种回连处理方式：

  • 方式一（公版外部回连） ：适用于开发者自行管理蓝牙连接（见 3.1），收到回连回调后由开发者自己完成回连；

  • 方式二（SDK 内置回连，推荐） ：SDK 内部通过 JLOtaReConnectMgr 自动完成“扫描 → 连接 → 认证 → 查询设备信息 → 继续升级”，开发者无需自己实现回连策略。

3.3.1. 方式一：公版外部回连

整体流程：

  1. 连接设备并获取设备信息（cmdTargetFeature）；

  2. 调用 cmdOTAData:Result: 发起 OTA 升级；

  3. 收到 JL_OTAResultReconnect / JL_OTAResultReconnectWithMacAddr 回调；

  4. 读取 otaManager.otaReconnectType 判断回连方式，自行扫描并连接设备；

  5. 回连成功并重新获取设备信息后，调用 cmdOtaDataIIResult: 继续升级。

回连回调示例（结合 3.1 外部蓝牙场景）：

 1[otaManager cmdOTAData:otaData Result:^(JL_OTAResult result, float progress) {
 2    if (result == JL_OTAResultReconnect ||
 3        result == JL_OTAResultReconnectWithMacAddr) {
 4        JL_OTAReconnectType type = otaManager.otaReconnectType;
 5        if (type == JL_OTAReconnectTypeMACAddr) {
 6            // MAC 方式：取设备 MAC 地址，扫描并连接广播包中 MAC 一致的设备
 7            JLModel_Device *model = [self.mAssist.mCmdManager outputDeviceModel];
 8            NSString *mac = model.bleAddr;
 9        } else {
10            // UUID 方式：用上次连接的 peripheral UUID 重新扫描连接
11            NSString *uuid = self.lastUUID;
12        }
13    } else if (result == JL_OTAResultSuccess) {
14        // 升级成功
15    }
16}];

10// }

重要

  • cmdOtaDataIIResult: 会复用上一次 cmdOTAData: 传入的升级数据继续升级；若数据已被清空，需重新调用 cmdOTAData:Result:。

  • 回连成功、重新连接并完成握手后，必须 重新执行一次 cmdTargetFeature，SDK 需要据此重新协商升级状态。

  • MAC 地址回连依赖 JL_AdvParse 库解析广播包；未导入该库时无法使用 MAC 方式回连。

3.3.2. 方式二：SDK 内置回连（推荐）

使用 cmdUpgrade:Option:Result: 接口，SDK 内部通过 JLOtaReConnectMgr 自动完成“扫描 → 连接 → 认证 → 查询设备信息 → 继续升级”的整个回连过程，开发者无需自己实现扫描/连接/认证逻辑。

示例：

 1NSData *otaData = [[NSData alloc] initWithContentsOfFile:otaFilePath];
 2
 3// 1. 配置回连选项（默认值一般无需修改）
 4JLOtaReConnectOption *option = [JLOtaReConnectOption defaultOption];
 5option.serviceUUID      = @"AE00";   // 服务 UUID，默认 AE00
 6option.writeUUID        = @"AE01";   // 写特征 UUID，默认 AE01
 7option.readUUID         = @"AE02";   // 读特征 UUID，默认 AE02
 8option.deviceAuthorize  = YES;       // 是否需要设备认证（握手配对），默认 YES
 9option.authKey          = nil;       // 握手配对秘钥，默认 nil（使用 SDK 默认）
10option.isWriteWithResponse = NO;     // 是否带响应写，默认 NO
11
12// 2. 使用内置回连接口发起升级
13JL_OTAManager *otaManager = [JL_OTAManager getOTAManager];
14[otaManager cmdUpgrade:otaData Option:option Result:^(JL_OTAResult result, float progress) {
15    if (result == JL_OTAResultUpgrading) {
16        // 正在升级
17    } else if (result == JL_OTAResultSuccess) {
18        // 升级成功
19    } else if (result == JL_OTAResultReboot) {
20        // 设备重启
21    } else {
22        // 其余错误码见 JL_OTAResult
23    }
24}];

JLOtaReConnectOption 参数说明：

 1@interface JLOtaReConnectOption : NSObject
 2/// 是否需要使用设备认证（握手配对），对应 JL_HashPair 库
 3@property (assign, nonatomic) BOOL deviceAuthorize;
 4/// 握手(配对)秘钥
 5@property (strong, nonatomic) NSData *__nullable authKey;
 6/// 设备服务 UUID，默认 AE00
 7@property (strong, nonatomic) NSString *serviceUUID;
 8/// 写特征 UUID，默认 AE01
 9@property (strong, nonatomic) NSString *writeUUID;
10/// 读特征 UUID，默认 AE02
11@property (strong, nonatomic) NSString *readUUID;
12/// 是否需要带响应的写方式，默认 NO
13@property (assign, nonatomic) BOOL isWriteWithResponse;
14@end

警告

  • 使用 cmdUpgrade:Option:Result: 时，升级状态只能通过 Result 回调 获取，不可使用 JL_OTAManagerDelegate 的代理回调（otaUpgradeResult:Progress:）。

  • option 传 nil 时，SDK 内部使用 [JLOtaReConnectOption defaultOption] 默认配置。

  • 内置回连依赖 JL_HashPair （设备认证）和 JL_AdvParse （MAC 地址回连）；若工程未导入这两个库，认证或 MAC 回连会失败，SDK 会输出 warning 日志。

  • 内置回连的扫描/连接在 SDK 内部完成，开发者此时 不要 同时用自己的蓝牙对象去连接该设备，避免连接冲突。

3.3.3. 相关接口速查

  • - (void)cmdOTAData:Result:：开始 OTA 升级（公版流程，回连需外部处理）；

  • - (void)cmdOtaDataIIResult:：单备份升级特有，回连成功后再次发起升级使用；

  • - (void)cmdUpgrade:Option:Result:：单备份升级特有，SDK 内部实现回连；

  • - (BOOL)cmdOtaIsRelinking：OTA 单备份是否正在回连；

  • @property JL_OTAReconnectType otaReconnectType：OTA 升级回连方式（SDK 自动判断并写入）；

  • JLOtaReConnectOption：回连选项；

  • JLOtaReConnectMgr：SDK 内部回连管理器（一般无需直接使用）。
