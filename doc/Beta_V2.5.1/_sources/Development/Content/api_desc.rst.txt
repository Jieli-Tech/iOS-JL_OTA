3.使用JL_BLEKit.xcframework蓝牙连接方式
=========================================

JL_BLEKit.xcframework依赖于其他的SDK，所以在导入时应包含以下：

.. code-block::

    JL_OTALib.xcframework——OTA升级业务库
    JL_AdvParse.xcframework——杰理蓝牙设备广播包解析业务库
    JL_HashPair.xcframework——设备认证业务库
    JLLogHelper.xcframework——日志打印业务库


.. important::
    
    在OTA过程中不允许进行其他命令的交互
    

3.1. SDK外部蓝牙管理
-----------------------

外部蓝牙管理，在使用 JL_BLEKit.xcframework 的同时，在蓝牙管理部分交由 **外边（开发者自定义蓝牙）统筹管理** ，可保障使用时的多样化。

**参考Demo：「 JL_OTA项目的 BleByAssist文件夹」**
**支持的功能** ：

- BLE设备握手连接；
- 获取设备信息；
- OTA升级能实现；
- 注意：相对于 **3.2.2** 中描述的所有BLE操作都需自行实现；

**会用到的类** ：

- **JL_Assist** ：部署SDK类；(必须)
- **JL_ManagerM** ：命令处理中心，所有的命令操作都集中于此；(必须)
- **JLModel_Device** ：设备信息存储的数据模型；(必须)

**BLE参数** ：

- **【服务号】** ：AE00
- **【写】特征值** ：AE01
- **【读 】特征值** ：AE02

                weakSelf.mBlePeripheral = peripheral;

            }
        }];
    }

3.2. SDK内部蓝牙管理
----------------------------------

以下实现方法基于JL_BLEKit.xcframework的内部集成蓝牙连接方法，开发者无需管理蓝牙对象，只专注升级业务即可。

**参考Demo：「 JL_OTA项目的 SDKBleManager文件夹」**

**1. 支持的功能** ：

- BLE设备的扫描、连接、断开、收发数据、回连功能；
- BLE设备过滤；
- BLE设备握手连接；
- BLE连接服务和特征值设置；
- 获取设备信息；
- OTA升级能实现；

**2. 会用到的类** ：

- **JL_BLEUsage**  ：可设置BLE过滤、握手、参数；查看蓝牙状态；
- **JL_Entity** ：BLE设备的模型类，记录设备的相关信息（如名字、UUID、UID、PID等）；
- **JL_BLEMultiple** ：BLE扫描、连接、断开、回连；
- **JL_ManagerM** ：获取设备信息、OTA操作；

3.3. OTA单备份回连
-----------------------

单备份固件的设备在 OTA 升级时需要先下载 BootLoader（Loader）。设备下载完 Loader 后会重启进入 Loader 模式，此时 BLE 连接断开，需要重新扫描并连接设备，再继续发送剩余的升级数据，这个过程称为 **回连**。双备份固件的设备升级时不会断开连接，无需回连。

.. note::

   升级过程中可通过 ``JL_OTAResult`` 回调中的以下状态判断是否需要回连：

   - ``JL_OTAResultReconnect`` (0x09)：需要回连，使用设备 UUID 定位；
   - ``JL_OTAResultReconnectWithMacAddr`` (0xfc)：需要回连，使用杰理广播包中的 MAC 地址定位；
   - ``JL_OTAResultReconnectUpdateSource`` (0xfe)：需要回连（资源升级场景）；
   - ``JL_OTAResultDisconnect`` (0xfd)：OTA 过程中设备断开。

SDK 会根据设备能力自动判断回连方式，并写入 ``JL_OTAManager.otaReconnectType``：

.. code-block:: obj-c
    :linenos:

    typedef NS_ENUM(UInt8, JL_OTAReconnectType) {
        JL_OTAReconnectTypeUUID    = 0x00, // OTA升级回连使用 UUID
        JL_OTAReconnectTypeMACAddr = 0x01, // OTA升级回连使用 MAC 地址
    };

杰理提供了两种回连处理方式：

- **方式一（公版外部回连）** ：适用于开发者自行管理蓝牙连接（见 3.1），收到回连回调后由开发者自己完成回连；
- **方式二（SDK 内置回连，推荐）** ：SDK 内部通过 ``JLOtaReConnectMgr`` 自动完成“扫描 → 连接 → 认证 → 查询设备信息 → 继续升级”，开发者无需自己实现回连策略。


3.3.1. 方式一：公版外部回连
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

整体流程：

1. 连接设备并获取设备信息（``cmdTargetFeature``）；
2. 调用 ``cmdOTAData:Result:`` 发起 OTA 升级；
3. 收到 ``JL_OTAResultReconnect`` / ``JL_OTAResultReconnectWithMacAddr`` 回调；
4. 读取 ``otaManager.otaReconnectType`` 判断回连方式，自行扫描并连接设备；
5. 回连成功并重新获取设备信息后，调用 ``cmdOtaDataIIResult:`` 继续升级。

回连回调示例（结合 3.1 外部蓝牙场景）：

.. code-block:: obj-c
    :linenos:

    [otaManager cmdOTAData:otaData Result:^(JL_OTAResult result, float progress) {
        if (result == JL_OTAResultReconnect ||
            result == JL_OTAResultReconnectWithMacAddr) {
            JL_OTAReconnectType type = otaManager.otaReconnectType;
            if (type == JL_OTAReconnectTypeMACAddr) {
                // MAC 方式：取设备 MAC 地址，扫描并连接广播包中 MAC 一致的设备
                JLModel_Device *model = [self.mAssist.mCmdManager outputDeviceModel];
                NSString *mac = model.bleAddr;
            } else {
                // UUID 方式：用上次连接的 peripheral UUID 重新扫描连接
                NSString *uuid = self.lastUUID;
            }
        } else if (result == JL_OTAResultSuccess) {
            // 升级成功
        }
    }];

回连成功并重新获取设备信息后，继续升级：

.. code-block:: obj-c
    :linenos:

    // 回连成功后，必须先重新获取设备信息，SDK 才能继续升级
    [otaManager cmdTargetFeature];

    // 获取设备信息的结果通过 JL_OTAManagerDelegate 的 otaFeatureResult: 回调返回，
    // 在该回调中再调用 OTA 升级 II 继续发送剩余数据：
    // - (void)otaFeatureResult:(JL_OTAManager *)manager {
    //     [manager cmdOtaDataIIResult:^(JL_OTAResult result, float progress) {
    //         // 处理后续升级回调（进度、成功、失败等）
    //     }];
    // }

.. important::

    - ``cmdOtaDataIIResult:`` 会复用上一次 ``cmdOTAData:`` 传入的升级数据继续升级；若数据已被清空，需重新调用 ``cmdOTAData:Result:``。
    - 回连成功、重新连接并完成握手后，**必须** 重新执行一次 ``cmdTargetFeature``，SDK 需要据此重新协商升级状态。
    - MAC 地址回连依赖 ``JL_AdvParse`` 库解析广播包；未导入该库时无法使用 MAC 方式回连。


3.3.2. 方式二：SDK 内置回连（推荐）
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

使用 ``cmdUpgrade:Option:Result:`` 接口，SDK 内部通过 ``JLOtaReConnectMgr`` 自动完成“扫描 → 连接 → 认证 → 查询设备信息 → 继续升级”的整个回连过程，开发者无需自己实现扫描/连接/认证逻辑。

示例：

.. code-block:: obj-c
    :linenos:

    NSData *otaData = [[NSData alloc] initWithContentsOfFile:otaFilePath];

    // 1. 配置回连选项（默认值一般无需修改）
    JLOtaReConnectOption *option = [JLOtaReConnectOption defaultOption];
    option.serviceUUID      = @"AE00";   // 服务 UUID，默认 AE00
    option.writeUUID        = @"AE01";   // 写特征 UUID，默认 AE01
    option.readUUID         = @"AE02";   // 读特征 UUID，默认 AE02
    option.deviceAuthorize  = YES;       // 是否需要设备认证（握手配对），默认 YES
    option.authKey          = nil;       // 握手配对秘钥，默认 nil（使用 SDK 默认）
    option.isWriteWithResponse = NO;     // 是否带响应写，默认 NO

    // 2. 使用内置回连接口发起升级
    JL_OTAManager *otaManager = [JL_OTAManager getOTAManager];
    [otaManager cmdUpgrade:otaData Option:option Result:^(JL_OTAResult result, float progress) {
        if (result == JL_OTAResultUpgrading) {
            // 正在升级
        } else if (result == JL_OTAResultSuccess) {
            // 升级成功
        } else if (result == JL_OTAResultReboot) {
            // 设备重启
        } else {
            // 其余错误码见 JL_OTAResult
        }
    }];

``JLOtaReConnectOption`` 参数说明：

.. code-block:: obj-c
    :linenos:

    @interface JLOtaReConnectOption : NSObject
    /// 是否需要使用设备认证（握手配对），对应 JL_HashPair 库
    @property (assign, nonatomic) BOOL deviceAuthorize;
    /// 握手(配对)秘钥
    @property (strong, nonatomic) NSData *__nullable authKey;
    /// 设备服务 UUID，默认 AE00
    @property (strong, nonatomic) NSString *serviceUUID;
    /// 写特征 UUID，默认 AE01
    @property (strong, nonatomic) NSString *writeUUID;
    /// 读特征 UUID，默认 AE02
    @property (strong, nonatomic) NSString *readUUID;
    /// 是否需要带响应的写方式，默认 NO
    @property (assign, nonatomic) BOOL isWriteWithResponse;
    @end

.. warning::

    - 使用 ``cmdUpgrade:Option:Result:`` 时，升级状态只能通过 **Result 回调** 获取，**不可使用** ``JL_OTAManagerDelegate`` 的代理回调（``otaUpgradeResult:Progress:``）。
    - ``option`` 传 ``nil`` 时，SDK 内部使用 ``[JLOtaReConnectOption defaultOption]`` 默认配置。
    - 内置回连依赖 ``JL_HashPair`` （设备认证）和 ``JL_AdvParse`` （MAC 地址回连）；若工程未导入这两个库，认证或 MAC 回连会失败，SDK 会输出 warning 日志。
    - 内置回连的扫描/连接在 SDK 内部完成，开发者此时 **不要** 同时用自己的蓝牙对象去连接该设备，避免连接冲突。


3.3.3. 相关接口速查
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

- ``- (void)cmdOTAData:Result:``：开始 OTA 升级（公版流程，回连需外部处理）；
- ``- (void)cmdOtaDataIIResult:``：单备份升级特有，回连成功后再次发起升级使用；
- ``- (void)cmdUpgrade:Option:Result:``：单备份升级特有，SDK 内部实现回连；
- ``- (BOOL)cmdOtaIsRelinking``：OTA 单备份是否正在回连；
- ``@property JL_OTAReconnectType otaReconnectType``：OTA 升级回连方式（SDK 自动判断并写入）；
- ``JLOtaReConnectOption``：回连选项；
- ``JLOtaReConnectMgr``：SDK 内部回连管理器（一般无需直接使用）。
